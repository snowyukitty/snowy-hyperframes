這份報告的結論很直接：做 HyperFrames 研究影片，成本不是單一月費，而是一個工作流組合。Codex、Pi 加 GitHub Copilot、Claude Code 的差別，主要在媒體完整度、自動化深度、使用限制和重跑成本。

成本模型

把 research-to-video 拆成七層

Research
搜尋、讀來源、引用整理、可信度分層。
Agent Work
推理、分鏡、資料結構、HTML/CSS/腳本。
Media
圖片生成、TTS、字幕、音訊重生、時間軸。
Render / QA
HyperFrames lint、validate、inspect、render、人工抽查。
公式：projectCost = 月費攤提 + AI usage + 搜尋 + 圖片 + TTS + render + QA

我把成本拆成七層：研究搜尋，推理與編碼，圖片生成，配音，字幕，渲染與檢查，以及日後維護。月費只能覆蓋其中一部分；真正決定長期成本的，是哪一層可以穩定重跑，哪一層需要額外 API 或人工補洞。

Codex workflow

最像端到端研究影片工作台

強項

研究、檔案編輯、生圖、TTS、字幕、HyperFrames 檢查可在同一操作回路完成。

成本型態

固定訂閱攤提為主；若改走 API，模型、web search、GPT-Image-2 都需逐項計價。

風險

內建能力與用量受方案、會話、模型可用性影響；長專案要保存 prompts 與資料層。

Codex workflow 最適合我們目前這類研究影片。它能在同一輪裡查資料、建立檔案、生成圖片、呼叫 Edge-TTS、跑 HyperFrames 檢查。它的現金邊際成本低，但會受到方案用量、內建生圖可用性與工作階段長度影響。

Pi 加 GitHub Copilot 的優勢是可重用、可封裝、可接多種 provider。若你有學生或 Copilot 方案，固定成本可能很低。但 Copilot 本身不等於圖片生成、搜尋 API 或 TTS；要做完整影片，還是要把 Tavily、Brave、Edge-TTS、OpenAI Codex 生圖或其他工具接好。

Claude Code workflow

長上下文與程式碼品質強，媒體工廠要外接

適合

大型 codebase 理解、重構、設計評審、長文檔整理、複雜前端與腳本修改。

注意

Pro/Max 用量與 Claude app 共用；若 `ANTHROPIC_API_KEY` 存在，可能變成 API 計費。

來源：Claude plan docs；Claude Code billing docs；Claude API pricing。

Claude Code 的長處是長上下文、程式碼理解、重構和大型專案推理。對 HyperFrames 這種前端加資料加自動化的專案，它可以很強；但它不是完整媒體工廠。圖片、搜尋、TTS、字幕校準和渲染，通常還需要外部工具或 API credit。

以 Snowy 的工作來看，小型兩到三分鐘影片，若已有訂閱與 Edge-TTS，本金幾乎是月費攤提。中型五分鐘報告，成本會轉向圖片重生、搜尋次數和字幕時間。大型十幾分鐘或基準研究，最貴的反而是上下文管理、QA、重跑穩定性，以及把結果記錄成可複用流程。

隱性成本

價格頁之外，才是真實風險

限流與動態配額

訂閱不等於無限；模型與工作負載會改變可用量。

Auth 與 API key

provider token、OAuth、API key 混用時，容易錯走付費路徑。

媒體一致性

圖片、旁白、字幕、時間軸每重跑一次都可能產生 QA 成本。

隱性成本不能忽略。訂閱工具可能有動態限制；Copilot AI credit 會影響代理和 CLI 功能；Claude Code 若設定 API key，可能轉成 API 計費；圖片模型和 TTS 服務也會變。對長期專案來說，成本控制其實是風險控制。

Snowy 採用策略

三條 workflow 不互斥，應該分工

Codex

主線出片：研究、素材、TTS、字幕、HyperFrames 驗證。

Pi

可重跑工具台：packages、providers、search、批次腳本、成本 ledger。

Claude Code

深層審核：長上下文、架構、重構、複雜前端和腳本可靠性。

建議：每個 project 保留 `cost-model.json`、`research.json`、`storyboard.json`、TTS 發音稿、render 指令與 retrospective。

我的建議是三條 workflow 各司其職。Codex 作為第一條主線，負責高品質研究影片的端到端產出。Pi 作為可重跑的工具台，用 Copilot 或其他 provider 降低自動化成本。Claude Code 用在大型程式碼、長上下文和架構審核。每個專案都要記錄訂閱、API、圖片、TTS、渲染和人工 QA 的成本，這會成為 Snowy HyperFrames 的長期資產。
